1. Общие сведения

1.1 Наименование системы. 

MediaPulse - веб-приложение для планирования задач и ведения медиаплана для медиа студенческого совета.


1.2 Основание для разработки. 

Задание на курсовую работу по дисциплине «Модели данных».

1.3 Исполнитель

Исполнитель: студент группы ИУК5-52Б Руденко А.Е.
Руководитель: Кириллов В.Ю


2. Назначение системы

2.1 Назначение системы

Система предназначена для участников медиа студенческого совета и позволяет вести общую доску задач, 
распределять задачи между участниками, формировать медиаплан публикаций. Система заменяет переписки единым рабочим
пространством.

2.2 Цель создания системы

Сократить время на согласование и постановку задач, обеспечить прозрачность статуса каждой публикации
и исключить потерю задач в чате.


3. Объект автоматизации и участники

3.1 Объект автоматизации

Деятельность медиацентра студсовета по планированию, распределению и контролю задач,
а также по ведению медиаплана публикаций.

3.2 Участники процесса

Гость - не выполнивший вход, доступ к регистрации, входу и доске по ссылке просмотра.

Участник группы - зарегистрированный пользователь, состоящий в доске, берет задачи, закрывает их, может назначать себя отвественным.

Руководитель - зарегестрированный пользователь, с правом создавать задачи, вести медиаплан, управлять 
количеством участников, назначать задачи.

Администратор - сотрудник оператора платформы, управляет учетными записями, 
тестирует, не имеет доступа к содержимому задач.

3.3 Ключевые термины

Доска - группа участников с общей доской и общим медиапланном.

Задача - отдельное дело группы, название, описание, приоритет, срок, отвественный/е, статус.

Главный по задаче (отвественный) - участник группы, назначенный отвечать за выполненния задачи.

Публикация - задача особого типа, входящая в медиаплан: канал, дата выхода, время выхода, статус публикации.

Медиаплан - упорядоченный по даам список публикаци редакции на период (месяц).

Недельный список - предоставление задач, срок или дата публикации которых попадает в текущую неделю.

Архив - представление завершенных задач, убранных с активной доски, но сохраняемых в системе.


4. Функциональные требования

4.1 Гость

* Г-1. регистрация и вход\
* Г-2. Просмотр доски (группы) по ссылке доступа в режиме только чтение.

4.2 Участник группы
* П-1. Вход/выход, восстановление пароля, редактирование профиля.
* П-2. Канбан-доска. Личная доска участника: колонки по статусам задачи,
Перемещение задач, фильтры по редактированию, задаче. (?)
* П-3. общая доска группы. Все задачи, участник видит задачи своей группы, но не других.
* П-4. Задачи. Создание, редактирование, смена статуса, приоритет, срок, описание, привязка к публикации.
* П-5. Недельный список задач. Представление "Неделя": задачи со сроком или датой публикации в текущей неделе,
добавление задачи прямо в список.
* П-6. Медиаплан. Таблица публикаций: дата, канал, ответственный, статус, ссылка на пост.
* П-7. Назначение главного по задаче. Любой участник может назначить себя ответственным; переназначение на другого участника доступно только руководителю.
* П-8. Проекты и теги. Проект — рубрика/кампания; тег — канал или формат (VK, Telegram, сторис, видео). Скрытие проектов и тегов без удаления задач.
* П-9. Статистика. Сводка за период: задачи по статусам, публикации, нагрузка по отвественным.
* П-10. Архив задач. Завершенные задачи могут быть перемещены в архив автоматически сразу после отметки "завершено". 

4.3 Администратор
* А-1. Просмотр списка пользователей и состояния учетных записей.
* А-2. Блокировка/разблокировка учетной записи. Содержимое задач и медиаплана администратору недоступно.
