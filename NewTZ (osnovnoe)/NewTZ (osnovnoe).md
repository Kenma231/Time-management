1. Общие сведения

1.1 Наименование системы.

MediaPulse — веб-приложение для планирования задач и ведения медиаплана для медиа студенческого совета.

1.2 Основание для разработки.

Задание на курсовую работу по дисциплине «Модели данных».

1.3 Исполнитель

Исполнитель: студент группы ИУК5-52Б Руденко А.Е.

Руководитель: Кириллов В.Ю.

2. Назначение системы

2.1 Назначение системы

Система предназначена для участников медиа студенческого совета и позволяет вести общую доску задач,

распределять задачи между участниками, формировать медиаплан публикаций. Система заменяет переписки единым рабочим

пространством.

2.2 Цель создания системы

Сократить время на согласование и постановку задач, обеспечить прозрачность статуса каждой публикации

и исключить потерю задач в чате.

3. Объект автоматизации и участники

3.1 Объект автоматизации

Деятельность медиацентра студсовета по планированию, распределению и контролю задач,

а также по ведению медиаплана публикаций.

3.2 Участники процесса

Гость — не выполнивший вход, доступ к регистрации, входу и доске по ссылке просмотра.

Участник группы — зарегистрированный пользователь, состоящий в доске, отмечает себя ответственным на задачу, закрывает задачи.

Руководитель — зарегистрированный пользователь с правом создавать задачи, вести медиаплан, управлять количеством участников, назначать и переназначать отвественного.

Администратор — сотрудник оператора платформы, управляет учетными записями,

тестирует, не имеет доступа к содержимому задач и медиаплану.

3.3 Ключевые термины

Доска — рабочее пространство группы, на котором отображаются задачи.

Группа — сообщество участников медиа с общей доской и общим медиапланом.

Задача — отдельное дело группы, название, описание, приоритет, срок, ответственный/е, статус, теги.

Главный по задаче (ответственный) — участник группы, назначенный отвечать за выполнение задачи.

Публикация — задача особого типа, входящая в медиаплан: канал, дата выхода, время выхода, статус публикации.

Медиаплан — упорядоченный по датам список публикаций редакции на период.

Недельный список — представление задач, срок или дата публикации которых попадает в текущую неделю.

Архив — представление завершенных задач, убранных с активной доски, но сохраняемых в системе.

Статус задачи — одно из состояний: "Идея", "Новая", "В работе", «На согласовании», «Завершено», «Опубликовано».

4. Функциональные требования

4.1 Гость
* Г-1. Регистрация и вход.
* Г-2. Просмотр доски (группы) по ссылке доступа в режиме только чтение.

4.2 Участник группы
* П-1. Вход/выход, восстановление пароля, редактирование профиля.
* П-2. Канбан-доска. Личная доска участника: колонки по статусам задачи, перемещение задач, фильтры по группе, проекту, ответственному.
* П-3. Общая доска группы. Все задачи, участник видит задачи своей группы, но не других.
* П-4. Задачи. Создание, редактирование, смена статуса, приоритет, срок, описание, привязка к публикации.
* П-5. Недельный список задач. Представление «Неделя»: задачи со сроком или датой публикации в текущей неделе, добавление задачи прямо в список.
* П-6. Медиаплан. Таблица публикаций: дата, время, канал, ответственный, статус, ссылка на пост.
* П-7. Назначение главного по задаче. Любой участник может назначить себя ответственным; переназначение на другого участника доступно только руководителю.
* П-8. Проекты и теги. Проект — вид (рубрика/новость); тег — канал или формат (VK, Telegram, сторис, видео).
* П-9. Статистика. Сводка за период: задачи по статусам, публикации, нагрузка по ответственным.
* П-10. Архив задач. Завершенные задачи могут быть перемещены в архив автоматически сразу после отметки «завершено». Архивные задачи не отображаются на доске и в недельном списке, доступны в представлении «Архив» с фильтрами по периоду и ответственному.
* П-11. Ссылка на просмотр доски. Руководитель формирует ссылку на доску группы, по ссылке доступен просмотр задач и медиаплана в режиме «только чтение» без входа и регистрации. Руководитель может отозвать ссылку — после отзыва доступ прекращается; при повторном формировании создаётся новая ссылка. Страница по ссылке закрыта от индексации поисковыми системами.
* П-12. Проверка дублей. При создании задачи система сама проверяет наличие активной задачи с таким же названием в той же группе и предупреждает пользователя, предлагая открыть существующую или подтвердить создание новой. Жесткий запрет не применяется.

4.3 Администратор
* А-1. Просмотр списка пользователей и состояния учетных записей.
* А-2. Блокировка/разблокировка учетной записи. Содержимое задач и медиаплана администратору недоступно.

5. Требования к данным

|Сущность|Ключевые атрибуты|
|---------|----------------|
|Пользователь|имя, e-mail, хеш пароля, подтверждение адреса, состояние учётной записи|
|Доска|название, состояние|
|Группа|название, состояние|
|Участник группы|пользователь, доска, роль|
|Задача|название, описание, приоритет, срок, статус, ответственный, проект, дата создания, дата смены статуса, признак архива, дата архивации, теги|
|Публикация|задача, канал, статус публикации, дата публикации, время публикации|
|Статистика|тип, период, данные за период|

6. Требования к интерфейсу и эксплуатации
* Веб-приложение, работа в браузере без установки; русский язык интерфейса.
* Поддержка Chrome, Firefox, Safari, Яндекс Браузер (две последние стабильные версии).
* Без горизонтальной прокрутки при ширине от 360 px; светлая и тёмная темы.
* Отклик интерфейса на действие ≤ 300 мс без учёта сети.
* HTTPS, хеширование паролей (bcrypt/Argon2), пароль от 8 символов, соответствие 152-ФЗ (данные на территории РФ).

7. Ограничения

Не входят: обмен сообщениями между пользователями, интеграция с внешними календарями и соцсетями, автопубликация постов, учёт времени по задачам и привычки.
